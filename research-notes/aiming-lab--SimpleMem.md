# SimpleMem｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/aiming-lab/SimpleMem/blob/main/README.md)；查閱日期：2026-09-28。

## 1. 這是什麼？

SimpleMem 是為 LLM Agent 提供長期記憶的研究與實作專案。它將對話或內容壓縮、儲存並檢索，統一套件可依輸入自動選擇文字或多模態後端，涵蓋文字、圖片、音訊和影片；另有可調整檢索策略的 EvolveMem。
它提供 Python 整合、Docker、MCP 服務與 Agent Skill。專案同時承載論文實驗，因此部分功能偏研究性。

## 2. 對我有什麼用？

你可以把它當作 Agent 跨工作階段記憶的候選方案，例如記住使用偏好、過往討論或多媒體資料，再在需要時檢索。MCP 介面可讓支援的聊天或 Coding Agent 使用文字記憶。
若你的權威資料仍在 Obsidian，SimpleMem 比較適合作為檢索和個人化層，不宜取代原始筆記。加入記憶前要考慮隱私、刪除、更正和錯誤摘要問題。

## 3. 使用情境

- 個人助理：保存偏好、已完成決策和跨對話背景。
- 長對話壓縮：將歷史內容整理成可檢索記憶，降低每次載入的上下文。
- 多媒體回憶：對圖片、音訊或影片建立可查詢記憶。
- 研究評估：比較不同記憶壓縮與檢索設定在資料集上的表現。

## 4. 我要怎麼用？

1. 若只想試用文字記憶，先依套件文件安裝 `simplemem`，準備 Python 環境與模型 API 設定。
2. 用少量非敏感對話測試加入記憶與搜尋，檢查保存內容是否忠於來源。
3. 需要 Codex 或其他 MCP 用戶端時，再選擇託管或本機 MCP 方式並設定存取。
4. 多模態、Docker與自動最佳化屬進階功能，應在文字流程、刪除與備份機制驗證後再加入。

## 5. 值不值得研究？

**有特定情境才值得深入。** 如果你要為 Agent 建立跨對話記憶，它很有研究價值；若目前 Obsidian 與 QMD 已足夠，先以小型比較測試確認它能增加多少召回與便利性，再決定是否承擔額外服務與資料治理成本。
