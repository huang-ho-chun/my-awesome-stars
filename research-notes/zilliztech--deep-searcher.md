# DeepSearcher｜GitHub 專案導覽

> 來源：[zilliztech/deep-searcher](https://github.com/zilliztech/deep-searcher) README；查閱日期：2026-10-19。

## 1. 這是什麼？

DeepSearcher 是一套可自行設定模型、Embedding 與向量資料庫的 Python 文件檢索及問答工具。它先載入本機資料，建立可搜尋的索引，再讓 LLM 根據檢索結果回答問題或撰寫報告；README 也提供選用的網頁載入方式。它比較像**用來組裝私有資料研究流程的開發工具**，不是現成的個人筆記桌面 App。

## 2. 對我有什麼用？

如果你要讓 AI 搜尋一批自己的文件，並問「這些資料有哪些共同觀點？」或「請根據資料整理一份報告」，它提供了一條可程式化的路徑。你可以試著用不敏感的文件建立小型知識庫，再評估回答是否能對應到原文。

你目前使用 Obsidian 與本機搜尋時，DeepSearcher 比較適合當**需要自行開發研究式問答功能**的候選，而不是直接取代既有筆記流程。資料是否送往外部模型，取決於你選用的 LLM 與 Embedding 供應者，私有資料要先核對設定。

## 3. 使用情境

- **個人資料研究**：把一批文章、報告或專案文件載入後做跨文件提問。
- **開發者原型**：測試不同 LLM、Embedding 與 Milvus 等向量資料庫的組合。
- **團隊知識問答**：在能管理資料來源與模型服務的環境中，建立內部查詢流程。

## 4. 我要怎麼用？

README 建議 Python 3.10。先建立虛擬環境並 `pip install deepsearcher`；選定 LLM、Embedding 與向量資料庫設定，準備相應的 API key 或服務。官方快速範例使用 OpenAI，設定模型後以 `load_from_local_files` 載入本機路徑，再呼叫 `query("問題")` 取得答案。網頁載入是選用功能，範例需要 Firecrawl API key。

你可先用少量公開文件測試結果與成本。若重點只是立刻有 GUI 可以用，先看現成 RAG 平台可能更省事。

## 5. 值不值得研究？

**有特定情境才有用。** 想開發自己的資料研究流程時值得試；若只是整理與搜尋個人 Obsidian 筆記，先確認既有工具的不足，再決定是否投入模型、索引及服務設定。
