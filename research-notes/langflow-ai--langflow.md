# langflow 專案指南

來源：[langflow-ai/langflow 官方 README](https://github.com/langflow-ai/langflow/blob/HEAD/README.md)；查閱日期：2026-09-16。

## 1. 這是什麼？

視覺化 AI 工作流與 Agent 建構平台。把模型、提示詞、資料來源與工具接成可檢查的流程；可用桌面版、Python 套件或 Docker 啟動，編排後再透過 API 供其他程式呼叫。

## 2. 對我有什麼用？

你能在不先寫完整 Python 整合程式的情況下，確認模型、資料和人工確認點如何連動。對既有測試腳本，最實際的價值是先驗證 AI 後處理流程，再決定是否值得正式接入。

## 3. 使用情境

若要替伺服器測試報告做『讀取結果→摘要→人工審核』原型，拖拉節點能快速看清資料流；它不會代替你現有 Shell／Python 測試邏輯。

先用一份已去識別的測試摘要建立流程，分別比較不同模型與提示詞輸出的差異；也可做文件問答雛形，確認每個節點的輸入輸出是否可回溯。

## 4. 我要怎麼用？

依 README 選 Windows/macOS 桌面版，或準備 Python 3.10–3.14 與 uv 安裝套件；也可用 Docker。啟動服務後在瀏覽器連接元件、試跑流程，再視需要用 API 串接。先在本機以小資料測試，部署前檢查憑證與存取控制。

README 的本機快速路徑是 uv 安裝後執行 langflow run，Docker 範例則將服務對應至 7860 埠。這讓你能先用瀏覽器驗證一條流程，再決定是否接入既有 Python 報告腳本。

## 5. 值不值得研究？

有特定情境才有用：若你要讓同事檢視與調整 AI 後處理流程，視覺化編排值得試；一次性腳本則未必需要平台。
