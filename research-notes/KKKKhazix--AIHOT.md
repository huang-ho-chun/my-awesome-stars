# AIHOT｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/KKKKhazix/AIHOT/blob/main/README.md)；查閱日期：2026-09-30。

## 1. 這是什麼？

AIHOT 是一套可自行架設的行業熱點網站框架。它會從多種資訊來源收集內容，先去重與預篩，再讓大型語言模型獨立評分兩次，為入選內容撰寫中文標題、摘要與推薦理由，最後把不同來源對同一事件的報導聚在一起，依獨立來源數與時間衰減計算熱度，產生每日、每週和每月簡報。

它提供網站前台、管理後台、選文流程、事件聚簇、熱度排行、搜尋、RSS、公開 API、MCP 與 `llms.txt`。專案附帶 18 個公開海外 AI 資訊源作為示範，但不包含 AIHOT 正式站的完整信源或營運資料。作者將它定位為線上系統的開源快照，而不是已為所有產業打磨完成的通用產品。

## 2. 對我有什麼用？

你可以把它改造成自己關心領域的資訊站，例如 AI 工具、Agent、英文學習、職涯或其他產業。與單純 RSS 閱讀器相比，它會先依你定義的標準篩選內容，再把重複報導聚成事件，能減少同一消息反覆出現。

它也很適合當成你現有 Follow Builders 或個人簡報流程的進階參考：前者偏向使用既定來源取得摘要，AIHOT 則讓你自行控制信源、分類、提示詞、入選門檻、品牌與部署。不過你需要維護 Docker、PostgreSQL、模型 API、抓取流程和內容品質，成本明顯高於直接使用現成摘要服務。

## 3. 使用情境

- **個人 AI 情報站**：追蹤官方部落格、技術媒體、X 帳號與其他來源，合併重複事件並產生日報。
- **特定產業監測**：改成金融、法律、HR、供應鏈或其他領域，由熟悉產業的人定義重要性。
- **團隊內部簡報**：固定產生日報、週報與月報，供成員快速閱讀並回到原始來源。
- **Agent 資料入口**：透過 RSS、API、MCP 或 `llms.txt` 讓 Agent 讀取已整理的內容。
- **篩選規則實驗**：使用人工標註樣本校準提示詞和門檻，觀察選文與聚簇品質。

## 4. 我要怎麼用？

1. 先準備 Docker，以及一個 OpenAI 相容的模型 API Key。若想建立自己的獨立站，可用 GitHub Template 建立倉庫；若要持續合併上游更新，則可先 Fork。
2. 複製倉庫後，使用 `node scripts/init-env.ts --llm-key <API Key>` 建立環境設定，再執行 `docker compose up -d --build`。
3. 開啟 `http://localhost:3000` 查看網站，管理後台位於 `/admin`；管理員密碼保存在本機 `.env`。
4. 在 `industry/` 內修改站名、分類、主題、信源、提示詞、入選門檻與品牌。可以讓 Codex 先閱讀 `AGENTS.md` 和 `docs/customize.md`，再依你的領域進行調整。
5. 不要直接大規模上線。先用一批自己標註的重要／不重要資料執行選文評測，檢查錯選、漏選、來源歸屬與事件誤合併，再調整評分標準和門檻。
6. 正式公開前，依部署文件設定網域、HTTPS、備份、更新、模型預算上限與告警；同時確認各信源的抓取條款與內容使用權限。

## 5. 值不值得研究？

**有明確的長期資訊監測需求時很值得研究。** 它把信源管理、AI 篩選、事件聚簇、日報和 Agent 介面整合得相當完整，也允許把你的產業判斷寫進提示詞與門檻。

對你來說，最有價值的方式是先把它當作 Follow Builders 與現有收藏整理流程的比較對象，用少量公開來源測試一週。若篩選結果確實比現有摘要更貼近需求，再投入自架與維運；如果只需要閱讀 AI 新聞，現有的低維護摘要工具會更省時間。
