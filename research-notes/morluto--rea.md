# REA｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/morluto/rea/blob/main/README.md)；查閱日期：2026-10-09。

## 1. 這是什麼？

REA（Reverse Engineer Anything）是給 Codex 等 Agent 使用的逆向分析工具，提供 MCP 與命令列介面。它可分析 JavaScript／Electron 應用、原生執行檔、網站及其他支援的目標，協助追查某項功能的運作路徑，並附上找到的證據與限制。不同目標需要不同工具：JavaScript 靜態分析相對容易開始，原生程式則可能需要 Hopper、Ghidra 或 IDA。

## 2. 對我有什麼用？

你若遇到只有成品、沒有原始碼的工具，卻想了解某個具體功能怎麼運作，可以讓 Agent 用 REA 釐清。例如研究一個 Electron 應用如何處理剪貼簿、匯入檔案或呼叫本機功能，再評估能否在自己的工具重做類似體驗。它也能幫你把「猜測」與「從檔案或執行行為確認的事實」分開。

這個工具適合有明確分析目標時使用。若你只是想判斷 GitHub 專案是否值得安裝，先讀 README、文件與範例通常更快。

## 3. 使用情境

- **功能研究**：追查既有桌面應用某個可觀察功能的資料流程。
- **Electron 專案盤點**：查看模組、匯入、路由及 IPC 關係。
- **原生程式分析**：搭配反組譯工具查看呼叫、字串、符號與參照。
- **網站行為檢查**：檢查頁面結構、腳本及網路互動，並保留證據。

## 4. 我要怎麼用？

1. 安裝符合 README 要求的 Node.js 與 npm；目前文件列出 Node 22.19+、24.11+ 或 26+。
2. 執行專案的 setup 流程，選擇 Codex 等要接入的 Agent，檢查它將修改的設定後完成註冊，再重新啟動 Agent。
3. 指定合法可分析的本機檔案或應用，以及一個具體問題，例如「這個搜尋功能怎麼找到結果？請列證據與未知處」。
4. 先用 JavaScript／Electron 範例確認流程；若要分析原生執行檔，再安裝並設定支援的分析器。
5. 核對 REA 的輸出證據與限制，再決定是否據此實作或進一步調查。

不想先接入 MCP，也可用命令列對本機 JavaScript 應用目錄做單次分析。

## 5. 值不值得研究？

**有具體逆向問題時很有用。** 它把多種分析工具接到 Agent，適合需要可追溯證據的功能研究；對日常閱讀開源專案則通常太重。
