# TREK｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/liketrek/TREK/blob/main/README.md)；查閱日期：2026-09-28。

## 1. 這是什麼？

TREK 是可自行架設的旅遊規劃 Web 應用，集中管理行程日期、地點、地圖、預算、文件、待辦與打包清單。它支援多人即時協作、PWA、SSO 與外掛，也能選擇開啟 MCP 和訂位資訊擷取功能。
它比較像家庭或小團體共用的旅行工作區，而不是單純列景點的行程表。資料放在自己的伺服器上，適合想保有控制權的人。

## 2. 對我有什麼用？

你可以用它把散落在聊天訊息、試算表、地圖收藏與筆記中的旅行資料集中起來。多人可一起調整每日安排、分攤費用、追蹤待辦與攜帶物品，出發後也能用手機的 PWA 查看。
若你想讓 Codex 或其他 MCP 用戶端協助建立行程、更新清單或整理預算，TREK 的 MCP 介面有進一步整合空間；這是選配功能，需要自行設定權限與維運。

## 3. 使用情境

- 家庭旅行：共同排景點、住宿與交通，並維護兒童用品或孕期用品清單。
- 多人自由行：一起編輯日程、費用、預約文件與待辦。
- 自架個人旅行資料庫：保留歷次旅程、去過的國家與收藏地點。
- Agent 輔助規劃：透過 MCP 在授權範圍內讀寫旅程資料。

## 4. 我要怎麼用？

1. 最快方式是準備 Docker，產生加密金鑰後啟動官方映像，並掛載資料與上傳目錄。
2. 開啟 `http://localhost:3000`，用首次啟動建立的管理員帳號登入；正式使用前應設定固定的管理員帳密。
3. 建立旅程、加入日期與地點，再依需要啟用費用、文件、清單、協作等模組。
4. 若要從外網使用，再按照文件設定反向代理、HTTPS、備份與更新；MCP、AI 擷取及第三方外掛可等基本流程穩定後再開。

## 5. 值不值得研究？

**很適合有多人旅行規劃需求、願意維護 Docker 服務的人。** 功能比一般行程表完整，也符合資料自主管理。若只偶爾排一日遊，維運成本可能高於收益，可以先收藏，等有大型旅行時再部署。
