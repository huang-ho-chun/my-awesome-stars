# Anatomy｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/wheresryan22/anatomy/blob/main/README.md)；查閱日期：2026-10-14。

## 1. 這是什麼？

Anatomy 是給 Codex 等 Agent 使用的繪圖 Skill，專門把技術概念做成立體視角的「機械解說圖」。它會把抽象流程轉成一個能運作的實體物件，細畫零件、位置和動作，再輸出可互動的說明頁。核心是 SVG；需要火焰、水、光等效果時可加入 WebGL，另有仍屬 beta 的 3D 模式。成品可為單頁 HTML、獨立 SVG 或 React 元件。

它的強項是機器、儀表、工具等有具體構造和運動的題材，並非一般流程圖或統計圖表工具。

## 2. 對我有什麼用？

如果你想把技術教學寫得更好懂，可以用 Anatomy 製作「零件如何配合」的互動圖。例如用鎖的機構解釋快取鍵比對，或用水流與閥門解釋限流器。讀者能透過滑鼠或鍵盤看到狀態變化，比一張靜態示意圖更容易理解運作過程。

對你而言，它較適合偶爾用在需要深入解釋的文章、教學頁或作品展示。若只是整理 GitHub 專案關係、筆記流程或數據，使用 SeeCode、draw.io 或一般圖表工具通常更直接。

## 3. 使用情境

- **技術概念教學**：把限流、快取或連線池等機制比喻成可操作的物件。
- **產品或設備說明**：逐一展示機器部件及其動作。
- **互動文章**：將圖嵌入網頁，讓讀者自己操作並查看數值變化。
- **靜態素材**：輸出 SVG，放進文件或簡報作為精緻插圖。

## 4. 我要怎麼用？

1. 準備 Node.js 20.10 以上；如需執行專案的畫面檢查，也準備 Chrome 或 Chromium。
2. 依 README 安裝 Codex Skill，例如執行 `npx skills add wheresryan22/anatomy -g -a codex`，確認 `anatomy/SKILL.md` 已放在 Codex 可讀的 Skills 位置。
3. 在 Codex 輸入 `$anatomy`，說明想解釋的概念、真實數值、目標讀者，以及要 HTML、SVG 或 React 輸出。
4. 先檢查一個小型範例的零件、動作與文字，再讓 Agent 修正。需要公開使用時，另外檢查行動裝置表現與無動態效果時是否仍能看懂。

它的製作與逐部件檢查可能花較長時間；先做單一機制比整套系統更合適。

## 5. 值不值得研究？

**有具體機械式解說題材時值得使用。** 它能做出一般框線圖難以呈現的互動細節，但對清單、一般流程圖、統計圖表及人物插畫幫助不大。
