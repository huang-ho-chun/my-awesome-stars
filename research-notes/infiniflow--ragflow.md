# ragflow｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/infiniflow/ragflow/blob/HEAD/README.md)；查閱日期：2026-09-16。

## 1. 這是什麼？

可自行部署的 RAG 問答平台，重視文件解析、分塊、檢索、引用與 Agent 工作流程。它把資料集、模型和對話介面整合成服務，適合讓團隊對文件提問，而非單純轉檔。

## 2. 對我有什麼用？

你的伺服器設定、操作文件和測試報告若需要多人查詢，RAGFlow 可作為知識服務的候選。它的引用功能有助回查原文，但回答仍須核對來源；私有資料先從隔離測試集開始。

## 3. 使用情境

選一批已公開或已去識別的伺服器手冊，測試跨文件問答、版本差異和引用位置。觀察表格、掃描頁與專有名詞是否被正確解析，再判斷能否用於內部支援。

## 4. 我要怎麼用？

先閱讀 README 的自託管前置需求；在獨立環境複製專案，依說明設定 `.env`，以 Docker Compose 啟動 CPU 服務，再開啟網頁建立知識庫、匯入少量文件、設定模型並試問。記錄資源消耗和引用品質；暫不接主 Obsidian 庫。

## 5. 值不值得研究？

評估時要先定義問題集：至少包含能回答、不能回答、跨版本互相矛盾三類。記錄每題引用是否指向正確頁段，以及新增文件後是否需重新建索引；若這些條件未達標，就先維持原來以檔案搜尋與人工查證的方式。

**有特定情境才有用。**適合多人共用文件問答，但部署與維運比你目前單人檢索工作重。
