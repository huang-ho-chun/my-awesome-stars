# supermemory｜GitHub 專案導覽

> 來源：[專案 README](https://github.com/supermemoryai/supermemory/blob/main/README.md)；查閱日期：2026-09-22。

## 1. 這是什麼？

supermemory 是供 AI 助理與 AI 應用使用的記憶和上下文引擎。它會從對話擷取值得保留的事實與偏好，維護長期和近期的使用者檔案，處理資訊更新、矛盾與過期內容，並在之後的對話中找回相關記憶。它也整合文件 RAG、混合搜尋、檔案處理，以及 Google Drive、Gmail、Notion、OneDrive 和 GitHub 等資料連接器。

它同時提供現成的 AI 工具外掛與 MCP、給開發者使用的 API，以及可在本機執行的版本。它比較像 AI 的**共用記憶層與知識檢索服務**，不是一般筆記軟體。

## 2. 對我有什麼用？

你會在不同任務中反覆使用 Codex，也希望 AI 記得偏好的工作方式、專案背景與先前決定。supermemory 可以讓相容的 AI 工具在新對話開始時取得個人偏好與近期活動，並在需要時搜尋舊記憶。對長期專案而言，可以減少每次重新說明背景的時間。

你也可以用專案或客戶標籤分隔記憶，或把文件與對話一起搜尋。若將來開發自己的 Agent，API 可直接提供記憶、使用者檔案與 RAG，省去自行設計向量資料庫、切塊和檢索流程。

要注意的是，自動記憶不等於內容一定正確。個人資料、工作資訊與推論都可能被錯誤擷取或過期，仍要能查看、修正或刪除。雲端 MCP/API 牽涉資料交給外部服務；涉及私人筆記、客戶資料或公司機密時，應先確認儲存、刪除與帳號條款，或評估本機自架版本。

## 3. 使用情境

- **跨對話協作：** 讓 AI 記得你的格式偏好、專案背景、已做決定和待處理事項。
- **分開不同領域：** 用 container tag 區隔私人、工作、客戶或不同 Repository 的記憶。
- **個人知識搜尋：** 同時檢索對話記憶與匯入文件，取得和目前問題相關的上下文。
- **開發 AI 產品：** 透過 JavaScript 或 Python API 為 Agent 加入記憶、使用者檔案、混合搜尋和資料連接器。
- **本機實驗：** 在自己的電腦執行服務，搭配本機 embedding 或 Ollama，降低資料外傳需求。

## 4. 我要怎麼用？

最省力的方式是先從單一、非敏感的專案試用：

1. 若只是想替 Codex 或其他 AI 工具加記憶，依官方文件選擇對應外掛或 MCP，完成帳號與連線設定。
2. 建立專用的專案標籤，只加入一小組可驗證的偏好和背景。
3. 開啟新對話，測試它是否能正確找回內容，也試著更新或刪除一項已過期資訊。
4. 確認隔離、修正和刪除流程符合需求後，再逐步擴大範圍。

開發者可安裝 npm 或 Python 套件，使用 `add`、`profile` 和 `search` 等 API。若希望資料留在本機，可以使用 local 版本；它會在本機提供相同類型的 API，但仍需要理解模型、embedding、備份與存取權限設定。正式存放敏感資料前，不要只依賴「本機」或「開源」標示，仍要實際確認使用的模型端點和資料流向。

## 5. 值不值得研究？

**很適合我，可以實際使用。** 它直接對應跨對話記憶和長期專案背景的需求，但應先以低敏感資料做小規模測試。若你目前的 Codex 內建記憶已能滿足需求，則把它視為需要跨工具共享記憶或開發自有 Agent 時的進階選項。
