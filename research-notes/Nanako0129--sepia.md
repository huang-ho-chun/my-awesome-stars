# sepia｜GitHub 專案導覽

> 依 [專案 README](https://github.com/Nanako0129/sepia) 與相關文件於 2026-09-16 重寫；著重用途與使用判斷，不深入原始碼。

## 1. 這是什麼？

sepia 是給 AI Agent 的寫作 Skill，處理 AI 文字常見的制式、冗長與缺乏真實判斷等問題。它不只是替換幾個詞，而是依文字類型調整表達方式；README 包含專業寫作與敘事等入口。它比較像一套可由 Codex、Claude Code 等 Agent 套用的寫作規則，不是獨立文字編輯器。

## 2. 對我有什麼用？

你會請 Codex 寫技術文件、Issue／PR 說明與除錯紀錄。sepia 的專業寫作方向能幫你把「為了提升品質」這類空話換成可查的決策、證據與後續動作。例如整理一次 server 問題時，保留發生時間、已嘗試但失敗的方法、真正原因與修復結果，而不是產生一篇漂亮卻難追查的文章。

## 3. 使用情境

- **工程溝通**：讓 PR 或 Issue 回覆先回答問題，再放證據和檔案位置。
- **事故與除錯紀錄**：清楚保留時間線、嘗試、原因與待辦。
- **技術文章或心得**：減少制式過場，保留你自己的觀察與判斷。小說相關規則與你目前工作較遠，可先略過。

## 4. 我要怎麼用？

1. 按 README 的 [Install](https://github.com/Nanako0129/sepia#install) 選擇 Codex、Claude Code 或跨 Agent Skills CLI 的安裝方式；可選使用者範圍或單一專案範圍。
2. 挑一篇你熟悉且能核對事實的草稿，請 Agent 用適合的專業寫作入口改寫，並明確要求保留數據、引用和不確定處。
3. 比較前後版本：是否更容易知道結論、證據與下一步；確認沒有把真實細節刪掉，再考慮加入日常流程。

## 5. 值不值得研究？

**很適合你試用，先從 Professional Writing 開始。** 它能改善 AI 協作文件的可讀性；但改寫後仍需人工核對事實，不能把「寫得自然」當成「寫得正確」。
