# mv-director｜GitHub 專案導覽

> 專案：https://github.com/Yari-tuber/mv-director

## 1. 這是什麼？

mv-director 是給 Codex、Claude Code 等 AI Coding Agent 使用的音樂 MV 製作 Skill。它會先用 Python 工具分析歌曲的分軌、節拍、小節、段落與歌詞時間，再要求 Agent 讀懂歌詞、逐句規劃分鏡，最後以 HTML Canvas 程式逐幀繪製 1080p、60 fps 影片；流程不依賴生成圖片。

專案把製作與驗收串成固定步驟：建立歌曲分析資料、拆解音樂、理解歌詞、選擇畫風、建立卡點表、繪製畫面、輸出草稿，以及用腳本檢查字幕時間、拍點命中、大時刻與死畫面。若檢查未達門檻，需修改後再輸出。

## 2. 對我有什麼用？

它適合把「請 AI 幫一首歌做 MV」從模糊提示詞變成可重複、可檢查的工作流程。對我而言，主要價值是：

- 將音訊分析、歌詞理解、視覺分鏡、程式動畫與成片驗收接在一起。
- 可搭配既有的 `lemo-opuscar`、`huashu-art-motion` 等風格庫，借用畫法規則，但不直接搬用別人的角色或場景。
- 以 `song.json`、`cues.json`、`plan.md` 和檢查報告保留製作依據，較容易追查字幕或卡點為何不準。
- 全部畫面由程式繪製，適合想保留可編輯來源、避免依賴生圖服務的影片實驗。

## 3. 使用情境

- 將一首歌曲的副歌或 30 秒片段製作成有逐句分鏡的音樂短片。
- 製作歌詞影片，讓文字盡量在實際開唱時間出現，而不是只平均分配整句時間。
- 測試不同程式動畫畫風如何配合同一段音樂，但保留原本的故事與鏡頭設計。
- 用自動檢查找出字幕過早／過晚、鏡頭沒有落在拍點、畫面長時間無變化等問題。
- 研究一套有階段門檻與可量化驗收的 Agent 影音製作流程。

## 4. 我要怎麼用？

1. 準備 Python 3.9 以上、ffmpeg，以及專案列出的 Python 套件；若要分軌與逐字強制對齊，還需安裝 Demucs、PyTorch 與 Transformers。
2. 將此 repository 安裝成 `mv-director` Skill，並執行 `python -I scripts/doctor.py` 檢查環境。
3. 在工作資料夾放入 MP3／WAV 歌曲和歌詞；帶時間的 LRC 最合適，也可使用逐行純文字歌詞。
4. 告訴 Agent 要製作的歌曲、片段與畫風來源。若未指定畫風，可讓它先讀風格庫並提出選項。
5. 依 Skill 的階段完成 `plan.md`、`cues.json` 與 `scene.js`，並先輸出逐句、逐小節和重要時刻的檢查圖。
6. 先渲染草稿並執行 `scripts/check.py`；修正未達標項目後，再輸出正式的 `out/mv.mp4`。

實際使用前要注意：強制對齊模型首次使用約需下載 1.8 GB；沒有安裝對齊模型時只能依整句 LRC 時間顯示歌詞。純文字歌詞需要整首對齊，因此專案限制歌曲最多五分鐘；已有時間的 LRC 不受這項限制。

## 5. 值不值得研究？

值得，但適合先用短片段做小規模測試。它的特色不是單一動畫效果，而是把「理解歌曲、逐句分鏡、卡節拍、程式繪圖、成片驗收」整理成一條有門檻的流程，對研究 Agent 如何完成較長的多階段影音任務很有參考價值。

成本也不低：需要 ffmpeg、瀏覽器渲染環境、音訊分軌與對齊模型；最終畫面品質仍取決於 Agent 寫出的 Canvas 程式，風格庫只能提供規則參考。因此建議先選 20–30 秒、包含副歌轉折的片段，確認分軌、對齊、渲染與檢查都能在本機跑通，再決定是否製作完整歌曲。
